# Teach Stu API and private state

`dev.ts` serves `/api` on loopback port 3001. Vite proxies development API requests. In production, Vercel sends `/api/**` to `api/index.ts`, which exports this Express app. Private keys never use a `VITE_` prefix.

## Two-layer live flow

`POST /api/topic` validates the title, fixed depth, and source documents, then asks the StepFun Judge for a grounded private rubric. The default Judge model is `step-5-preview`. Two samples run in parallel and the first that passes validation is kept, because a single sample's time ranges from about 35 to 85 seconds and some come back empty. Long notes are sampled evenly per page (headings first) to about 40,000 characters for this call. A citation that is not in the notes is dropped, along with any item left citing nothing, and the plan is kept only if it still passes every rubric rule. The rubric has `cover`, `explain`, and `connect` stages and opaque server-generated item IDs. Gist-only cover items reject equations, numbers, and edge details. Source IDs must match the submitted notes. The response contains only total and credited counts, percentage, mode, an opening message, and an authenticated encrypted state token. No rubric requirement text is returned.

`POST /api/teach` decrypts state and checks the document scope and revision. In teaching mode it calls **only Stu** (`step-3.7-flash`), appends the teacher message and Stu's reply to the sealed transcript, queues the teacher message for grading (`pendingJudge`), and returns at once with `judgePending: true`. Stu receives only depth, the visible transcript, a director note (a verified phrase of the teacher's from the previous grading, or the newest message), recent question style, and a **lesson**: the topic title, the names of its core ideas, and the one idea he should try to learn next. The server picks that idea from the rubric without showing it to him: the unfinished idea the teacher's newest message clearly matches (by its label, requirements and cited note text), otherwise the first idea whose gist is not credited yet. He never receives notes, source spans, rubric requirements, or private progress. The director note turns a Judge `off_topic` problem into steering back to that idea, and a `wrong` problem into Stu doubting the claim without being told the answer. Two samples race. A reply with no question, or longer than 700 characters, is rejected; one that asks more than one real question (a trailing "…, right?" doesn't count), runs past 450 characters or four sentences, or asks about two or more subject words that appear nowhere in the notes, rubric, idea names, title or teacher's words (the tangent guard; `STU_TOPIC_GUARD=off` disables it) is held back while the other sample runs, and used only if nothing better arrives. If both samples are rejected, one more pair runs.

`POST /api/judge` then grades every queued teacher message with the `step-5-preview` Judge, whose job is deliberately small: credits, revocations, and problems only. Its result passes Zod validation, and the server accepts credit or revocation only when it cites one of the queued teacher messages and a verbatim substring. Short affirmations, assistant messages, already-graded messages, altered quotes, unknown item IDs, and duplicate evidence cannot earn credit. Grounded wrong problems block and revoke affected items; revocation wins over simultaneous credit. The first verified problem becomes Stu's next director note; the Judge is told to report a message that is mainly a story, an anecdote, or facts outside the notes as `off_topic`. A failed grading leaves the messages queued for the next one. The browser never sends a new teaching message while a grading is in flight, so the sealed state stays linear.

Notes reach StepFun as short ids (`S1`, `S2`, …) with their page and text only; page boxes and long hash ids stay on the server, and cited short ids are mapped back before validation. All StepFun requests are streamed (`stream: true`) with `reasoning_effort: low` and per-role output and time limits inside Vercel's 180-second function limit. Rejected output is logged and returned with a content-free reason (cut off, invalid JSON, or the failing schema paths, plus token counts), and the rubric, Judge, and brief get one repair attempt that names the broken rule.

When all items are credited and no current factual problem remains, the same conversation enters **re-learn** mode and the grading response asks for one more `/api/judge` call. That call has `step-5-preview` write a source-grounded brief (verified teacher wording, corrections for earlier wrong teaching, one depth-appropriate quiz question), and Stu presents it as his teach-back. In re-learn mode each quiz answer goes to `/api/teach`, which writes a new brief and then Stu's reply in sequence. Re-learn messages may carry Judge-validated source citations. Teaching-mode Stu messages have none.

`STEPFUN_API_KEY` stays server-side. `STEPFUN_BASE_URL` defaults to `https://api.stepfun.ai/v1`; `STEPFUN_JUDGE_MODEL` defaults to `step-5-preview`; `STEPFUN_STU_MODEL` defaults to `step-3.7-flash`. `STEPFUN_MODEL` is a backward-compatible Judge fallback. `/api/config` reports key presence, **not** a successful connection. The live badge is true only after both validated calls complete and the Judge used `step-5-preview`. Deterministic samples cannot set it. The provider maps authentication, balance, rate limit, timeout, malformed output, and other failures to safe messages. It logs only role, model name, and duration, never notes, transcript, raw responses, or credentials. Contracts follow StepFun's [Chat Completions API](https://platform.stepfun.ai/docs/en/api-reference/chat/chat-completion-create), [JSON Schema guidance](https://platform.stepfun.ai/docs/en/guides/developer/json-mode), and [error guidance](https://platform.stepfun.ai/docs/en/guides/developer/exception).

## Debug and storage

`ENABLE_JUDGE_DEBUG=true` exposes the optional **Show Judge Evidence** control. The response includes only validated item IDs and teacher quotes, generic problem descriptions, sanitized focus, mistake acceptance, model names, and durations. Private requirements, hidden reasoning, provider bodies, and keys are excluded. It is off by default.

The private rubric, evidence, transcript, and mode are in an authenticated AES-GCM state token bound to topic ID and the actual extracted document text (and, with accounts on, to the account that started the topic). The browser persists that opaque token with local originals and drafts in IndexedDB. `.miso/state-key` is retained for compatibility; set `SESSION_SECRET` for a stable deployment secret. The API server has no document or conversation database; with accounts on, the browser also saves each session to the signed-in user's Supabase row and private `notes` folder. Deletion clears that data and the transient revision guard, but cannot retract provider requests.

Optional StepFun transcription and speech use the same server-side key as the Judge and Stu. The browser converts recordings to 16 kHz mono WAV in memory; audio is sent to StepFun only when requested. Typed use needs no microphone. Limits: five files, 20 MB and 100 pages per file, 300,000 extracted characters total, and 12 MB per recording. Public model endpoints are limited to 60 requests per 10 minutes per function instance, counted per account (plus 180 per IP) when accounts are on and per IP otherwise. OCR is unavailable.

## Accounts

`auth.ts` turns on Google sign-in (Supabase Auth) only when both `SUPABASE_URL` and `SUPABASE_ANON_KEY` are set; otherwise it does nothing. `/api/config` then returns `auth: { url, anonKey }` (else `null`), and the browser builds its Supabase client from it. Every other `/api` route needs `Authorization: Bearer <access token>`: the server refuses a token that can't be live (not a JWT, over 8 KB, no `sub`, expired) without a network call, then calls `GET <SUPABASE_URL>/auth/v1/user` with the anon key, admits only Google sign-ins (not anonymous, email or phone users), caches a valid answer for 60 seconds under a SHA-256 of the token (bounded; failures are never cached), and attaches `{ id, email }` to the request. No token or a rejected one returns `401 { code: 'AUTH_REQUIRED' }`; more than 30 failed checks from one IP in a minute return `429 AUTH_RATE_LIMIT`; Supabase being unreachable returns `503 AUTH_UNAVAILABLE`. `createTeachTopic` seals the caller's id into the topic state, and `openTeachState` refuses another account's token with `403 WRONG_ACCOUNT`; tokens sealed before accounts stay valid and are bound to the first account that uses them. Only the anon key is ever used. The table, policies and bucket are in `supabase/schema.sql`; setup is in [docs/ACCOUNTS.md](../docs/ACCOUNTS.md).

## Vercel deployment

`npm run build` creates the full frontend. `api/index.ts` exports the Express API as a Vercel Function. Add `STEPFUN_API_KEY` and a stable, random `SESSION_SECRET` to Vercel's Preview and Production environment settings. The `SESSION_SECRET` must remain the same across deployments so saved sessions stay readable. `vercel.json` configures the Vite build, same-origin `/api` routing, SPA fallback, and Fluid Compute. The Firebase Hosting-only build remains live until the Vercel preview is verified and the domain is moved.
