# Teach Stu API and private state

`dev.ts` serves `/api` on loopback port 3001. Vite proxies development API requests. In production, Vercel sends `/api/**` to `api/index.ts`, which exports this Express app. Private keys never use a `VITE_` prefix.

## Two-layer live flow

`POST /api/topic` validates the title, fixed depth, and source documents, then makes **one** StepFun Judge call to create a grounded private rubric. The default Judge model is `step-5-preview`. The rubric has `cover`, `explain`, and `connect` stages and opaque server-generated item IDs. Gist-only cover items reject equations, numbers, and edge details. Source IDs must match the submitted notes. The response contains only total and credited counts, percentage, mode, an opening message, and an authenticated encrypted state token. No rubric requirement text is returned.

`POST /api/teach` decrypts state, checks the document scope and revision, then calls the Judge and Stu **sequentially**. The Judge receives relevant source spans, the private rubric, fixed depth, teacher transcript, credit and revocation state, and quiz state. Its `step-5-preview` structured result passes Zod validation. The server accepts credit or revocation only when it cites a real user message and a verbatim substring. Short affirmations, assistant messages, altered quotes, unknown item IDs, and duplicate evidence cannot earn credit. Grounded wrong problems block and revoke affected items. Revocation wins over simultaneous credit. Focus is constrained to a teacher quote and a generic instruction; ungrounded focus or mistake is discarded or replaced. A proposed mistake cannot introduce new topic words absent from its teacher anchor.

Only then does the visible Stu call run, using `step-3.7-flash` by default. In **teaching** mode it receives only depth, the visible transcript, a sanitized director note, mode, and recent question style. It never receives notes, source spans, rubric content, or private progress. Stu's short, one-question response is validated. The new encrypted state and visible response are returned together only after both calls succeed. A Judge failure prevents Stu; a Stu failure leaves the old token usable for retry. A stale request is rejected by the revision gate.

When all items are credited and no current factual problem remains, the same conversation enters **re-learn** mode. The Judge creates a source-grounded brief using verified teacher wording and corrections for earlier wrong teaching. Stu receives that brief in re-learn mode and presents it in Stu's voice with one depth-appropriate quiz question. Re-learn messages may carry Judge-validated source citations. Teaching-mode Stu messages have none.

`STEPFUN_API_KEY` stays server-side. `STEPFUN_BASE_URL` defaults to `https://api.stepfun.ai/v1`; `STEPFUN_JUDGE_MODEL` defaults to `step-5-preview`; `STEPFUN_STU_MODEL` defaults to `step-3.7-flash`. `STEPFUN_MODEL` is a backward-compatible Judge fallback. `/api/config` reports key presence, **not** a successful connection. The live badge is true only after both validated calls complete and the Judge used `step-5-preview`. Deterministic samples cannot set it. The provider maps authentication, balance, rate limit, timeout, malformed output, and other failures to safe messages. It logs only role, model name, and duration, never notes, transcript, raw responses, or credentials. Contracts follow StepFun's [Chat Completions API](https://platform.stepfun.ai/docs/en/api-reference/chat/chat-completion-create), [JSON Schema guidance](https://platform.stepfun.ai/docs/en/guides/developer/json-mode), and [error guidance](https://platform.stepfun.ai/docs/en/guides/developer/exception).

## Debug and storage

`ENABLE_JUDGE_DEBUG=true` exposes the optional **Show Judge Evidence** control. The response includes only validated item IDs and teacher quotes, generic problem descriptions, sanitized focus, mistake acceptance, model names, and durations. Private requirements, hidden reasoning, provider bodies, and keys are excluded. It is off by default.

The private rubric, evidence, transcript, and mode are in an authenticated AES-GCM state token bound to topic ID and the actual extracted document text. The browser persists that opaque token with local originals and drafts in IndexedDB. `.miso/state-key` is retained for compatibility; set `SESSION_SECRET` for a stable deployment secret. The server has no document or conversation database. Local deletion clears browser data and the transient revision guard, but cannot retract provider requests.

Optional StepFun transcription and speech use the same server-side key as the Judge and Stu. The browser converts recordings to 16 kHz mono WAV in memory; audio is sent to StepFun only when requested. Typed use needs no microphone. Limits: five files, 20 MB and 100 pages per file, 300,000 extracted characters total, and 12 MB per recording. Public model endpoints are limited to 30 requests per IP per 10 minutes per function instance. OCR is unavailable.

## Vercel deployment

`npm run build` creates the full frontend. `api/index.ts` exports the Express API as a Vercel Function. Add `STEPFUN_API_KEY` and a stable, random `SESSION_SECRET` to Vercel's Preview and Production environment settings. The `SESSION_SECRET` must remain the same across deployments so saved sessions stay readable. `vercel.json` configures the Vite build, same-origin `/api` routing, SPA fallback, and Fluid Compute. The Firebase Hosting-only build remains live until the Vercel preview is verified and the domain is moved.
